# D7 (#35): the independent-oracle rule, now enforced rather than stated. Before #35 this
# project had no ProjectReference to DatabentoDotNet.Dbn at all, and its csproj called that
# absence "the rule this project must not break". #35 gave DatabentoDotNet.Historical its own
# reference to the codec, so this project now reaches it transitively and the build stopped
# enforcing anything by omission.
# The rule's actual content is narrower than "cannot see the codec": this harness must not
# manufacture the bytes it serves with the codec those bytes exist to check. A double that built
# its own fixtures with the same codec it exists to check would let a misreading of DBN's wire
# format sit in both and have them agree with each other — the same reasoning the mock gateway
# itself must never use the client it exists to test. SyntheticDbnFragment hand-builds DBN for
# that reason — see this project's csproj.
# Symbols is deliberately NOT banned here. It lives in DatabentoDotNet.Dbn too, but building a
# Symbols value never touches the bytes this harness serves, and the composition test this issue
# owes (Task 3) needs it.
# See the root BannedSymbols.txt for the line format this file follows, and for the RS0031
# gotcha that a comment line can trip: the analyzer keys each line by the text up to its first
# separator, so that prefix must not duplicate another line's, anywhere in the combined banned
# list (this file plus the root one). A bare comment line is the extreme case — its whole text
# is nothing, and two of those collide with each other — but this file's own drafting hit the
# same gotcha from a narrower angle: an earlier line echoed the root file's example line closely
# enough that the text ahead of its separator matched and the two collided as duplicates. Every
# comment line here is checked against that rule, not merely against writing a bare separator.
# One limit worth knowing, because nothing announces it: BannedApiAnalyzers does not diagnose a
# DocId it cannot resolve. A ban naming a type that no longer exists is not an error, or a warning,
# or anything at all — it simply matches nothing. So renaming or moving MetadataEncoder would turn
# the line below into a silent no-op and leave this file looking as though it still enforces the
# rule it describes. It resolves today, and the point is only that nothing would say otherwise.
